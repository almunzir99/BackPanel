## Plan: Identity-Based User Management Redesign (DRAFT)

This migration replaces the custom Admin/Role/Permission stack with ASP.NET Core Identity, using one-time data migration, single-role users, coarse role-based authorization, and manager global bypass. The redesign removes reflection-based permission checks and nested CRUD permission objects, then aligns Angular to consume role membership instead of dynamic permission properties. The approach is phased to keep login and core CRUD endpoints working while backend and frontend contracts are transitioned, then legacy permission infrastructure is removed.

**Steps**
1. Establish target auth model in [Infrastructure/BackPanel.Persistence/Database/AppDbContext.cs](Infrastructure/BackPanel.Persistence/Database/AppDbContext.cs) and [Presentation/BackPanel.WebApplication/Program.cs](Presentation/BackPanel.WebApplication/Program.cs): move to Identity (`AppUser`, `AppRole`) with JWT auth wired through Identity managers, keeping numeric keys and a single effective role per user.
2. Introduce Identity entities and mapping in Domain/Application layers by replacing custom password ownership in [Core/BackPanel.Domain/Entities/UserEntityBase.cs](Core/BackPanel.Domain/Entities/UserEntityBase.cs), [Core/BackPanel.Domain/Entities/Admin.cs](Core/BackPanel.Domain/Entities/Admin.cs), [Core/BackPanel.Domain/Entities/Role.cs](Core/BackPanel.Domain/Entities/Role.cs), and deprecating [Core/BackPanel.Domain/Entities/Permission.cs](Core/BackPanel.Domain/Entities/Permission.cs).
3. Build one-time EF migration set in [Infrastructure/BackPanel.Persistence/Migrations](Infrastructure/BackPanel.Persistence/Migrations): create Identity tables, copy users from `Admins` to `AspNetUsers`, copy roles from `Roles` to `AspNetRoles`, populate `AspNetUserRoles` from `Admin.RoleId`, map managers to Manager role, and preserve legacy IDs in transitional columns for reconciliation.
4. Replace token issuance and claims source in [Core/BackPanel.Application/Helpers/JwtHelper.cs](Core/BackPanel.Application/Helpers/JwtHelper.cs) and [Core/BackPanel.Application/Generic/Accounts/Commands/Handlers/AuthenticateCommandHandlerBase.cs](Core/BackPanel.Application/Generic/Accounts/Commands/Handlers/AuthenticateCommandHandlerBase.cs): emit stable role claims from Identity and remove `admin_role` + nested permission dependency.
5. Remove custom permission filter path by retiring [Core/BackPanel.Application/Attributes/Permissions/PermissionsAttribute.cs](Core/BackPanel.Application/Attributes/Permissions/PermissionsAttribute.cs) and [Core/BackPanel.Application/Features/Roles/Queries/Handlers/GetByTitleRoleQueryHandler.cs](Core/BackPanel.Application/Features/Roles/Queries/Handlers/GetByTitleRoleQueryHandler.cs); replace controller authorization with `[Authorize(Roles=...)]` and manager bypass policy.
6. Refactor controller bases in [Presentation/BackPanel.WebApplication/Areas/API/Controllers/Common/ApiController.cs](Presentation/BackPanel.WebApplication/Areas/API/Controllers/Common/ApiController.cs) and [Presentation/BackPanel.WebApplication/Areas/API/Controllers/Accounts/AccountBaseController.cs](Presentation/BackPanel.WebApplication/Areas/API/Controllers/Accounts/AccountBaseController.cs): remove `PermissionTitle`, normalize protected endpoints, and ensure create/update/delete are consistently authorized.
7. Redesign role contracts in [Core/BackPanel.Application/DTOs/RoleDto.cs](Core/BackPanel.Application/DTOs/RoleDto.cs), [Core/BackPanel.Application/DTOsRequests/RoleDtoRequest.cs](Core/BackPanel.Application/DTOsRequests/RoleDtoRequest.cs), and [Core/BackPanel.Application/Mapping/MappingProfile.cs](Core/BackPanel.Application/Mapping/MappingProfile.cs) to coarse role metadata only (name/description/status), dropping nested CRUD permission payloads.
8. Update Angular auth state to role-based membership in [Presentation/BackPanel.WebApplication/ClientApp/src/app/core/services/account.service.ts](Presentation/BackPanel.WebApplication/ClientApp/src/app/core/services/account.service.ts), [Presentation/BackPanel.WebApplication/ClientApp/src/app/app.component.ts](Presentation/BackPanel.WebApplication/ClientApp/src/app/app.component.ts), and [Presentation/BackPanel.WebApplication/ClientApp/src/app/core/models/role.model.ts](Presentation/BackPanel.WebApplication/ClientApp/src/app/core/models/role.model.ts): remove permission-object assumptions and store user roles (or single role + manager flag).
9. Replace route/menu authorization model in [Presentation/BackPanel.WebApplication/ClientApp/src/app/core/guards/permission.guard.ts](Presentation/BackPanel.WebApplication/ClientApp/src/app/core/guards/permission.guard.ts), [Presentation/BackPanel.WebApplication/ClientApp/src/app/dashboard/components/menu/menu.component.ts](Presentation/BackPanel.WebApplication/ClientApp/src/app/dashboard/components/menu/menu.component.ts), and [Presentation/BackPanel.WebApplication/ClientApp/src/app/dashboard/components/menu/menu.list.ts](Presentation/BackPanel.WebApplication/ClientApp/src/app/dashboard/components/menu/menu.list.ts): convert `permissionName` checks into `allowedRoles` checks with manager unconditional access.

Rebuild Roles/Admins UI flows for new contracts in [Presentation/BackPanel.WebApplication/ClientApp/src/app/dashboard/pages/roles/roles.component.ts](Presentation/BackPanel.WebApplication/ClientApp/src/app/dashboard/pages/roles/roles.component.ts), [Presentation/BackPanel.WebApplication/ClientApp/src/app/dashboard/pages/roles/roles.component.html](Presentation/BackPanel.WebApplication/ClientApp/src/app/dashboard/pages/roles/roles.component.html), and [Presentation/BackPanel.WebApplication/ClientApp/src/app/dashboard/pages/admins/admins.component.ts](Presentation/BackPanel.WebApplication/ClientApp/src/app/dashboard/pages/admins/admins.component.ts), keeping role selection in admin form and removing permission matrix UI.

Validate shared form compatibility in [Presentation/BackPanel.WebApplication/ClientApp/src/app/shared/components/form-builder/form-builder.component.html](Presentation/BackPanel.WebApplication/ClientApp/src/app/shared/components/form-builder/form-builder.component.html) for revised role/admin DTO shapes (especially selection controls and required validation paths).
12. Execute cleanup phase: remove dead permission enums/models/handlers and legacy migration artifacts tied to nested permissions, then update README migration notes in [README.md](README.md).

**Verification**
- Backend: run `dotnet build` and integration tests for authenticate/profile/admins/roles endpoints with role and manager scenarios; verify forbidden/allowed matrix on all CRUD routes.
- Data migration: run migration on seeded legacy DB snapshot, assert user count/role count/user-role mappings, and confirm manager accounts retain bypass behavior.
- Frontend: test login bootstrap, menu visibility, route guard behavior, role CRUD, admin create/update with role assignment, and profile flows.
- Regression: validate token refresh/login after role change, and ensure no endpoint still depends on `PermissionTitle`, `admin_role`, or nested permission DTOs.

**Decisions**
- Data strategy: one-time migration from legacy tables to Identity tables.
- Authorization model: role-only coarse authorization (no module CRUD permissions).
- Role cardinality: single effective role per user.
- Manager behavior: global bypass retained as explicit platform rule.
